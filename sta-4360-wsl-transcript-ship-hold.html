Default: ship

Two hung WSL file reads leave Chat UI stuck until Orca restarts.

Not diagnostics-only. No Chat UI change — same tab, same error line, same 30s wait.

Problem

Codex · auth-fix freezes mid-reply after Ubuntu’s files hang, and a retry of that same tab never comes back.

Fix

When the wait expires, Orca kills the hung file helper so this tab can show the existing retry line — and later resume — without a restart.

Does / does not

Does
  • Keep Codex · auth-fix usable after Ubuntu’s files hang: show the known retry line, then pick up the chat when Ubuntu answers again.
  • Leave a healthy Claude · debian-notes tab streaming while Ubuntu is the one that stalled.
  • Stop “restart Orca” from being the only recovery.
Does not
  • Change tab titles, bubbles, composer, or the “temporarily unavailable” wording.
  • Make a stopped or sleeping distro fast. The 30s wait is still there.
  • Touch macOS, Linux, SSH, or Windows chats that are not reading WSL files.

One term

Chat UI is not the live terminal. It is rereading the session file Ubuntu exposes to Windows. Orca lets two of those reads run at once. If both hang, this tab’s next read has nowhere to go.

The old check said yes to the next read

Same window as beat 2. Earlier change already stopped waiting after 30s. That is the wrong question.

Question the old code asked When
Did the 30s wait on Codex · auth-fix expire? Earlier change Yes
Did we stop this tab from waiting? Earlier change Yes
Can we start the replacement read of this same tab? Earlier change Yes
Did the hung file call actually leave Orca? Never asked —
Kill that hung call, then retry this tab / leave Debian alone This change Does

The visible wrong YES is the replacement. Bookkeeping said the next read of Codex · auth-fix could start. The first hung call was still sitting inside Orca. After two of those, both seats stay occupied until restart.

Who pays

Benefits Windows users with Chat UI or the session list pointed at WSL. Pays a short-lived helper process on those reads, plus the packaged Windows build must include it. If the helper is missing from the install, WSL Chat UI fails closed instead of hanging.

Decision

Ship — default The earlier timeout already taught the tab to stop waiting. This is the missing half: actually drop the hung read so the same tab can recover. Verify one packaged Windows build can still open a WSL Chat UI tab.
Hold if The helper is not in the Windows install, or killing it is unproven on a real hung Ubuntu share. Then the old “restart Orca” failure remains.
Wrong tool Do not retune the 30s message or add another spinner. The tab already knows how to complain. It cannot clear the hung read.
